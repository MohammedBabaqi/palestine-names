## عن المشروع

**أسماء لا تُنسى** مساحة تذكارية وتوثيقية للفلسطينيين الذين استُشهدوا في غزة؛ تجمع بين سرد بصري تفاعلي وأرشيف للأسماء قابل للبحث، لتمنح الزائر فرصة للتوقّف عند الاسم والعمر، واستحضار الإنسان الذي يمثّله كل سجل.

تأخذك التجربة عبر ستة فصول، تتشكّل فيها هيئات بشرية صغيرة في صورة عدد، وخريطة فلسطين، وشجرة زيتون، وكلمة **فلسطين**. ترافق هذه المشاهد قراءة للأسماء وإحصاءات مستمدة من القائمة المحمّلة، ضمن تصميم عربي بألوان الورق والحبر والزيتون.

> هؤلاء مَن وُثِّقَت أسماؤهم… وليسوا كلَّ مَن فقدنا.

## ماذا ستجد في الموقع؟

- **تجربة تذكارية تفاعلية:** رحلة بصرية تربط الأعداد بالأسماء، وتترك مساحة للقراءة والتأمّل.
- **أرشيف للأسماء:** البحث بالاسم العربي أو الإنجليزي، والتصفية حسب العمر، وترتيب النتائج والتنقّل بين صفحاتها وفتح تفاصيل كل سجل.
- **إحصاءات توثيقية:** عرض العدد والفئات العمرية اعتمادًا على البيانات المحمّلة، مع توضيح حدود ما تمثّله.
- **مساعد أرشيفي اختياري:** يتيح طرح أسئلة عن البيانات؛ ويبقى البحث والأرشيف متاحين من دون مفتاح لخدمة الذكاء الاصطناعي.
- **تجربة عربية قابلة للوصول:** دعم اتجاه القراءة من اليمين إلى اليسار، والتنقّل بلوحة المفاتيح، وتقليل الحركة وفق إعدادات الجهاز، وإتاحة النصوص والأرشيف عند تعذّر العرض ثلاثي الأبعاد.

**[ابدأ زيارة الموقع](https://palestine.babaqi.io)** أو **[انتقل مباشرة إلى الأرشيف](https://palestine.babaqi.io/archive)**.

## البيانات والتوثيق

يعتمد المشروع على [بيانات Tech For Palestine](https://data.techforpalestine.org/docs/killed-in-gaza/)، التي تنشر قوائم وزارة الصحة. تُحفظ نسبة البيانات إلى مصدرها، ويمكن الرجوع إليه للاطّلاع على منهجية النشر والتحديثات.

- يتحقّق الخادم من المصدر عند بدء التشغيل، ثم كل 24 ساعة أثناء تشغيله؛ **التحقّق اليومي لا يعني صدور قائمة أسماء جديدة كل يوم**.
- تُفحص البيانات قبل اعتمادها، ويُحتفظ بآخر نسخة سليمة إذا تعذّر التنزيل أو لم تجتز النسخة الجديدة التحقّق.
- تصف الأعداد والإحصاءات **الأشخاص الواردة أسماؤهم في القائمة المحمّلة**؛ ولا تمثّل بالضرورة إجمالي الشهداء المبلّغ عنه في التقارير الأخرى.
- التشكيلات البصرية تستخدم عيّنة من السجلات مراعاةً لأداء الأجهزة؛ أمّا الأرشيف والإحصاءات فيعتمدان على القائمة المحمّلة كاملة.
- خريطة فلسطين تشكيل تذكاري، وليست خريطة لمواقع الأشخاص. وتبقى الأعمار والتواريخ غير المعروفة غير معروفة.
- إجابات المساعد الآلي تحتاج إلى مراجعة السجلات والمصدر، ولا تحلّ محلّهما.

## About the project

**Palestine Names — أسماء لا تُنسى** brings together an Arabic visual memorial and a searchable archive of Palestinians killed in Gaza. Six narrative chapters connect human silhouettes, names and demographic information, inviting visitors to pause at the people represented by the records.

The archive supports Arabic and English name searches, exact-age filters, sorting, pagination and individual record details. Data comes from Tech For Palestine's publication of Ministry of Health lists. Counts describe the loaded names list; the visual formations use a sample and do not represent every reported casualty.

**[Explore the memorial](https://palestine.babaqi.io)** · **[Search the archive](https://palestine.babaqi.io/archive)** · **[Read the source documentation](https://data.techforpalestine.org/docs/killed-in-gaza/)**

## For developers

The frontend uses **Next.js, React, TypeScript and Three.js / React Three Fiber**. The backend uses **Python and FastAPI**, with an optional **LangChain / OpenRouter** archivist.

### Run locally

Requires **Node.js 22+** and **Python 3.11+**.

```sh
git clone https://github.com/MohammedBabaqi/palestine-names.git
cd palestine-names
```

Start the backend:

```sh
cd backend
python -m pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

In a separate terminal, from the repository root:

```sh
cd frontend
npm ci
npm run dev
```

Open [localhost:3000](http://localhost:3000). Backend API documentation is available at [127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

The memorial, archive and statistics work without an AI key. To enable the optional AI service, copy `backend/.env.example` to `backend/.env` and set `OPENROUTER_API_KEY`. Keep the key on the backend.

<details>
<summary><strong>Configuration and deployment</strong></summary>

| Variable | Used by | Default | Purpose |
| --- | --- | --- | --- |
| `DATA_SYNC_ENABLED` | Backend | `true` | Set to `false` to disable background data checks. |
| `DATA_CACHE_PATH` | Backend | `backend/.cache/names.json` | Writable persistent snapshot path. |
| `OPENROUTER_API_KEY` | Backend | Empty | Optional AI service authentication. |
| `API_URL` | Next.js server/build | `http://127.0.0.1:8000` | Backend origin used by the same-origin `/api` proxy. |
| `NEXT_PUBLIC_API_URL` | Frontend/build | `/api` | Optional direct API override; requires matching backend CORS. |

Run the backend as a persistent service with writable storage at `DATA_CACHE_PATH`. Set `API_URL` to the reachable backend origin before building the frontend.

A static-only or sleeping serverless backend cannot run the 24-hour background timer. For that setup, schedule the following command on a worker sharing the persistent snapshot:

```sh
cd backend
python -m data.sync
```

The running API detects atomic snapshot replacements without a restart. Inspect `/api/dataset` and refresh failure logs to monitor freshness.

</details>

<details>
<summary><strong>Data synchronization and provenance</strong></summary>

The backend reads the [versioned v3 CSV](https://data.techforpalestine.org/api/v3/killed-in-gaza.csv). It validates schema, complete rows, names, ages, dates, revisions and unique IDs before atomically replacing the records and their provenance. Corrections and removals replace the previous list. Invalid downloads and network or disk failures retain the last valid snapshot; the repository CSV provides an offline first-start fallback.

| Field | Meaning |
| --- | --- |
| `checked_at` | Last successful upstream check. |
| `refreshed_at` | Last change to downloaded content. |
| `source_revision` | The list's `update` value; not a calendar date. |
| `source_last_modified` | HTTP modification time; not a death date or coverage date. |
| `status` | Fresh, stale, or bundled fallback. A failed check or more than 48 hours since success marks data stale. |

Records without source IDs receive stable internal IDs and are labelled accordingly. Fractional ages are represented as completed years. Aggregate casualty reports are a separate dataset.

</details>

<details>
<summary><strong>Verification commands</strong></summary>

From `backend/`:

```sh
python -m unittest discover -s tests -v
```

From `frontend/`:

```sh
npm run lint
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright uses mocked API responses, so it does not require the live dataset or an AI key. The suite covers archive interactions, history, failure states, dialog focus, reduced motion, Arabic Markdown, mobile layouts and WebGL fallback. GitHub Actions runs backend and frontend checks on pull requests.

</details>
